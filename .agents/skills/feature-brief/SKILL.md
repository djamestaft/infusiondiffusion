# Feature brief

1. Read `PRODUCT.md`, `DESIGN.md`, `AGENTS.md`, and the relevant architecture or operations section.
2. Inspect the actual code and current stories before asking questions.
3. Write the user outcome, audience, in/out of scope, affected ownership boundaries, content source, responsive behavior, states, analytics needs, and failure behavior.
4. Express acceptance criteria as observable behaviors. Include accessibility, realistic content extremes, tests, preview evidence, and rollback considerations.
5. Identify decisions that require the product owner. Never hide them as implementation assumptions.
6. Route visual work through the product designer and data work through the content/commerce engineer before implementation.

Output: summary, decisions, acceptance criteria, affected systems, test evidence required, and unresolved questions.
