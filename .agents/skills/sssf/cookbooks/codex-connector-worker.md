# Bounded Codex Figma connector worker

Use only after a human approves an exact canonical file/node smoke and enables `workers.figma_codex.enabled`. Pi scopes and validates typed evidence; `adw_modules/codex_worker.py` alone launches bare `codex` in an isolated temporary cwd with `--ephemeral`, strict config, and read-only sandbox. It preflights only the official `figma` connector in memory; never login, copy credentials, or save raw responses.

Requests contain one file and 1–12 exact nodes. Before `exec`, preflight requires the official connector's `enabled_tools` to equal the request-compatible canonical read-only list; unknown, broadened, or modifying tools fail closed. The worker also supplies that exact list to `exec`. Each capture persists a sanitized typed `request.json` beside `evidence.json` and `result.json`; its manifest digest is included in the result hash and `worker_tool` trace binding. Results contain sanitized status, observed IDs, Approved labels, allowlisted calls, handoff-relative artifact hashes, the sanitized observed `codex --version`, and an internal provenance hash—not a cryptographic Figma signature. The parser is pinned to @openai/codex 0.147.0 official exec-event source `266c6920d9b82fe4d68959529565256b12a9be99` and MCP CLI/test source `420accf199e10bc908837ce5c7609b3bb9a38c8d`; incompatible list/get/JSONL shapes fail closed. The worker permits two 180-second attempts, two-second backoff, and a 370-second deadline; only timeout/disconnect/rate-limit/provider-5xx retry. It kills the process group on timeout or breach.

Record authorization before capture in a separate no-worker operation: `just figma-capture --record-approval --adw-id <session> --file-key <key> --node-id <id> --approved-by <configured-authority>`. It writes a target-bound audit record and approval artifact only. Then run `just figma-capture --adw-id <session> --file-key <key> --node-id <id>`; `--approved-by` is rejected for capture and cannot manufacture approval. The worker checks the pre-existing trusted trace for the exact target before connector preflight. Readiness requires one complete sanitized `worker_tool` row binding the exact final result and manifest hashes to the closed worker attempt. A missing static fact uses structured `unavailable` status and blocks regardless of wording. Capture and SDLC workflows finalize rejected runs on ordinary failure or cancellation after closing the worker. This is offline evidence only: retain the disabled default and require a separately human-authorized live smoke. It never builds, commits, merges, deploys, publishes, or rolls back.
